# 改进 B：VDA-S 窗口拼接漂移（第一批样本）

只改拼接，不改网络。脚本：

- `vda_windows.py`：把上游 `infer_video_depth` 拆成两步。
  - `predict_windows`：只做网络推理。
  - `stitch_official`：上游拼接的逐行拷贝。
  - `stitch_with`：可以换成别的拼接参数。
  - 上游 commit 为 4f5ae23，Apache-2.0 许可。
- `causal_shift.py`：因果检验。去掉开头 s 帧后重跑官方 VDA，看尺度下降是否跟着接缝一起移动。
- `run_b.py`：五个重新拼接的样本。都保留上游的 8 帧线性渐变。
  - B1-ov：只用 8 帧真实重叠帧做对齐。
  - B1-fg：只用前景像素。
  - B1-rob：改用 Huber 损失。
  - B2：所有窗口联合做 L1 对齐。
  - B3：B2 加一个均匀抽 32 帧的锚点窗口，只参与对齐。

```bash
python part3/improve_b/causal_shift.py
python part3/improve_b/run_b.py
python part2/video_depth/temporal_eval.py --out results/figures/part3/improve_b/temporal_eval --methods \
  "DA V2-S (frame-wise)|results/raw/part1b_da2/depth.npz" "VDA-S (video)|results/raw/part2b_vda/depth.npz" \
  "B1-ov|results/raw/p3_b_B1-ov/depth.npz|VDA-S (video)" "B1-fg|results/raw/p3_b_B1-fg/depth.npz|VDA-S (video)" \
  "B1-rob|results/raw/p3_b_B1-rob/depth.npz|VDA-S (video)" "B2 joint|results/raw/p3_b_B2/depth.npz|VDA-S (video)" \
  "B3 joint+anchor|results/raw/p3_b_B3/depth.npz|VDA-S (video)"
```

## 因果检验：下降来自拼接

| 起点 s | 本次运行的接缝区（原帧号）的尺度变化 | 原接缝区 24–31 / 46–53 的尺度变化 | 区外同长度的平均变化 |
| --- | --- | --- | --- |
| 0 | 24–31：−5.4%，46–53：−5.7% | （就是本次的接缝区） | 1.6% |
| 5 | 29–36：−6.6%，51–58：−7.8% | −0.9% / +2.0% | 1.8% |
| 11 | 35–42：−4.0%，57–64：−6.5% | +1.2% / +5.7% | 3.1% |
| 16 | 40–47：−5.6%，62–69：−8.0% | +0.4% / +1.3% | 1.8% |

接缝挪到哪里，下降就跟到哪里；原来的位置不再下降。所以漂移是拼接造成的，改进 B 有意义。

## 重新拼接的效果（Farnebäck；RAFT 结论相同）

| 指标 | VDA-S（官方） | B1-ov | B1-fg | B1-rob | B2 | B3 |
| --- | --- | --- | --- | --- | --- | --- |
| 接缝区 24–31 的尺度变化 | −5.36% | −0.38% | −0.29% | **−0.22%** | −2.18% | −1.25% |
| 接缝区 46–53 的尺度变化 | −5.66% | +2.15% | +2.31% | +2.48% | **+0.65%** | +1.38% |
| 接缝区 68–69 的尺度变化 | −2.64% | −1.64% | −1.62% | −1.65% | −2.12% | −2.37% |
| 相邻帧误差 | 0.0161 | 0.0169 | 0.0166 | 0.0167 | **0.0156** | 0.0161 |
| 最大相邻尺度跳变 | 1.87% | 1.01% | 0.97% | 0.99% | 1.42% | 1.63% |
| M1 尺度变化，k = 20 | 3.60% | 5.57% | 5.58% | 5.64% | 4.86% | 5.12% |
| L(t) 范围 | 9.5% | 10.9% | 10.8% | 11.0% | 8.5% | 9.5% |
| 超过 p98 的前景比例 | 7.4% | 11.3% | 11.1% | 11.2% | 9.1% | 10.0% |
| M3 帧间边缘 F1 | 0.894 | 0.894 | 0.894 | 0.894 | 0.864 | 0.894 |
| 对齐耗时 | 0.06 s | 0.04 s | 0.04 s | 0.5 s | 2.2 s | 4.9 s + 1.1 s 锚点前向 |

- **接缝跳变基本修好了**：
  - 改用真实重叠帧对齐（B1）后，24–31 的下降从 −5.4% 降到约 −0.3%；
  - 最大相邻跳变从 1.87% 降到约 1.0%。
- **但长程漂移变大了**：k = 20 的尺度变化从 3.6% 升到 5.6%。
  - 原因可以从 M1 轨迹图看出：VDA 在每个窗口内部有缓慢上升的趋势。原来接缝处的下降恰好抵消了这个趋势；修好接缝后，上升趋势一段段累积起来。
  - 输出整体变大，所以超过 p98 的比例也从 7.4% 升到 11%。
- B2 和 B3 把一部分长程约束（第 0 帧、锚点窗口）放进了对齐，k = 20 的漂移因此回落一些（4.9–5.1%），但还没回到 3.6%。

## 已发现的问题（下一轮要改）

1. **窗口内部的上升趋势**需要长程约束来压住。计划里的 B2+flow（跨窗口光流对）和更强的锚点（B3 的锚点也参与最终输出，或者提高锚点的权重）。
   另外要和 DA V2 的轨迹对照，判断这个上升是不是镜头运动带来的真实变化。
2. **B2 的偏移量偏大**（0.25–0.38，约为深度范围的 5–8%），导致 M3 边缘 F1 降到 0.864。可能是第 0 帧（大部分已经出画、以天空为主）的约束带偏了。下一轮试：去掉第 0 帧，或者给偏移加正则。
3. 68–69 只有 2 帧，是最后一个窗口里几乎全是补帧的特殊情况，可以单独处理。
